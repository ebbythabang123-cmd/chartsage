# Contributing to ChartSage

We love your input! We want to make contributing to ChartSage as easy and transparent as possible.

## Getting Started

1. Fork the repository
2. Clone your fork: `git clone https://github.com/YOUR_USERNAME/chartsage.git`
3. Create a branch: `git checkout -b feature/your-feature`
4. Make your changes
5. Push to your fork
6. Open a Pull Request

## Development Setup

```bash
# Install dependencies
npm install

# Setup environment
cp .env.example .env

# Start development server
npm run dev
```

## Code Style

- Use 2-space indentation
- Use camelCase for variables and functions
- Use PascalCase for classes
- Write meaningful commit messages
- Add comments for complex logic

## Testing

Before submitting a PR:

```bash
# Test endpoints with curl or Postman
curl -X GET http://localhost:5000/api/health
```

## Reporting Bugs

When reporting bugs, include:

- Description of the bug
- Steps to reproduce
- Expected behavior
- Actual behavior
- Your environment (OS, Node version, etc.)

## Feature Requests

Feature requests are welcome! Please describe:

- What problem does it solve?
- How would you like it to work?
- Any alternatives you've considered?

## Pull Request Process

1. Update README.md with any new features
2. Update SETUP.md if there are new setup steps
3. Ensure your code follows our style guide
4. Include a clear description of changes
5. Link any related issues
